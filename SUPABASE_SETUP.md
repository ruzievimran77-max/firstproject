# Подключение авторизации FuelParts KZ

Сайт остаётся статическим: серверного приложения и секретного ключа в браузере нет. Авторизация и пользовательские данные обслуживаются Supabase; доступ к таблицам ограничен RLS. Заказ из формы сохраняется как заявка, а наличие и итог подтверждает менеджер.

## 1. Создать бесплатный проект Supabase

1. Зарегистрируйтесь на [supabase.com](https://supabase.com/) и создайте проект на бесплатном тарифе.
2. Откройте **SQL Editor**, вставьте содержимое `supabase/migrations/20261126000000_account.sql` и выполните миграцию.
3. В **Project Settings → API** скопируйте **Project URL** и публичный **anon / publishable key**. Не используйте `service_role` / `secret` key.
4. Вставьте значения в `supabase-config.js`:

   ```js
   window.FUELPARTS_SUPABASE_CONFIG = {
       url: "ВАШ_PROJECT_URL",
       anonKey: "ВАШ_ПУБЛИЧНЫЙ_ANON_KEY"
   };
   ```

   `.env.example` — шаблон переменных для хостинга/сборки; браузер не читает `.env` напрямую. При публикации статического сайта значения должны попасть в конфигурацию, загружаемую до `java.js`. Публичный anon key допустим только при включённой RLS, секретные ключи сюда не помещайте.

## 2. Настроить адреса авторизации

В Supabase откройте **Authentication → URL Configuration**:

- **Site URL** — основной HTTPS-адрес опубликованного сайта.
- **Redirect URLs** — точные адреса сайта и локальной разработки, например `https://ваш-домен.kz/**` и `http://localhost:8000/**`.
- Для проверки локально используйте локальный HTTP-сервер, а не открытие `index.html` через `file://`.

В **Authentication → Providers → Email** включите вход по email. Для регистрации с подтверждением включите отправку писем и настройте SMTP/почтовый сервис, если стандартного лимита Supabase недостаточно.

## 3. Подключить Google OAuth

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и настройте **OAuth consent screen**.
2. Создайте OAuth Client ID типа **Web application**.
3. В Google OAuth client добавьте в **Authorized redirect URIs** callback из Supabase: откройте **Authentication → Providers → Google** и скопируйте показанный Callback URL (обычно `https://<project-ref>.supabase.co/auth/v1/callback`).
4. Вставьте Client ID и Client Secret только в **Supabase → Authentication → Providers → Google** и включите провайдер. Не добавляйте Google Client Secret в проект сайта.
5. Проверьте согласованные домены/redirect URLs в Google и Supabase, затем протестируйте вход с опубликованного HTTPS-домена.

## 4. Что уже хранится

- Профиль, избранное, корзина, сохранённые автомобили и заявки находятся в таблицах Supabase.
- RLS разрешает пользователю читать/менять только собственные профиль, корзину, избранное и автомобили. Историю заявок пользователь может только читать; создание идёт через проверяемую RPC-функцию.
- Статусы заявок меняются только доверенной стороной через Supabase Dashboard или отдельный сервер. Сайт не подделывает подтверждение покупки и не обрабатывает оплату.
- Фотография профиля задаётся HTTPS-ссылкой. Загрузка файлов в Storage намеренно не включена.
- Клиент использует стандартную PKCE-сессию Supabase с автоматическим обновлением токена. В этом статическом проекте нет серверной сессии с HttpOnly-cookie; для такого требования понадобится серверный слой.

Если Supabase не настроен, каталог продолжит работать, а форма аккаунта покажет, какие настройки отсутствуют. Для реального входа, сохранения данных, восстановления пароля и заявок завершите шаги выше.
